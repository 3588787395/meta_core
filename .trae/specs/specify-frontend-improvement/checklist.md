# Checklist

评审工程师需逐项检查并给出量化评分。总分 100 分，每项按权重计分；若任一项得分低于该项满分的 90%，视为该检查点不通过。所有检查点均通过后总分须大于 98 分方可进入下一任务。

## 评分规则

- 每项满分 = 权重 × 100
- 实际得分 = 满足子条款数量 / 子条款总数 × 该项满分
- 任一子条款存在严重问题（功能不可用、引入新路径、破坏既有功能），该子条款计 0 分
- 检查完成后在方框中标记：`- [x]` 表示通过，`- [ ]` 表示不通过

---

- [ ] **Check 1: 前端职责边界清晰（权重 15）**
  - [ ] `AppState` 中不再持有池运行时状态、事件队列、计时器队列等业务真值源
  - [ ] 事件时间归一化、TTL 计算、事件分类聚合、仿真时间换算等复杂逻辑已从前端移除
  - [ ] 前端保留的状态仅限纯 UI 状态（面板折叠、画布缩放、选中项、滚动位置）
  - [ ] 不存在股票池执行逻辑、条件计算等残留

- [ ] **Check 2: 表驱动 UI 唯一路径（权重 20）**
  - [ ] 属性面板渲染完全由 `config/ui/*.json` 配置表驱动，无硬编码节点类型分支
  - [ ] 顶部工具栏条目从配置表生成，与 HTML 中写死的条目一致但来源唯一
  - [ ] 右键菜单条目从配置表生成，上下文子菜单无重复/遗漏
  - [ ] 移动端溢出菜单与桌面菜单来源一致，不存在独立实现路径
  - [ ] 新增节点类型或字段时，仅需修改配置表即可生效

- [ ] **Check 3: 事件驱动唯一路径（权重 20）**
  - [ ] 前端仅通过单一 `EventSource('/api/events/stream')` 接收后端事件
  - [ ] 事件格式与 `core/event_bus.py` 事件契约对齐
  - [ ] 不存在前端伪造事件、独立事件队列作为真值源
  - [ ] 运行控制操作调用后端 API 后，UI 由后端推送的状态事件更新
  - [ ] 计时器队列数据来自后端 API，前端仅做展示

- [ ] **Check 4: 股票池功能正确且简洁（权重 25）**
  - [ ] 节点增删改查（备选池、转移条件、状态池、丢弃池、文字标签）工作正常
  - [ ] 连线增删改查与属性（条件/无条件、线形、描述文字、线条宽度）工作正常
  - [ ] 右键菜单（添加节点、属性、复制/剪切/粘贴、层级、删除、综合设置）工作正常
  - [ ] 导入导出（DZH XML、TDX XML、JSON）工作正常
  - [ ] 运行控制（开始、暂停、停止）与模式切换（设计/仿真/回放/实盘）工作正常
  - [ ] 事件面板正确展示后端事件，无前端推断的异常状态
  - [ ] 计时器队列、K线/公式面板展示正确

- [ ] **Check 5: 唯一正确路径，无多路径/兼容/特殊处理（权重 15）**
  - [ ] 不存在 `try old else new`、`if (legacy)`、`if (compat)` 等兼容分支
  - [ ] 同一功能只有唯一实现路径
  - [ ] 仿真/回放/实盘模式共享同一条执行路径，无特殊分支
  - [ ] 重复全局钩子（如 `window.timelineAddEvent`、`window.logSystemEvent`）已收敛
  - [ ] 未使用的变量、函数、DOM 引用、CSS 类已清理

- [ ] **Check 6: 设计文档与集成质量（权重 15）**
  - [ ] `DESIGN.md` 已更新前端架构边界说明
  - [ ] `docs/` 下相关文档已同步更新
  - [ ] 前端静态检查无新增错误
  - [ ] 现有测试（如有）无回归失败
  - [ ] 每个 Task 均有独立的 commit 并 push 到远程
