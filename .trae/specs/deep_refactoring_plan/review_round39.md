### 3. FormulaRouter 换 `_engine_methods`——这个替换有水平（概括力 +0.5，精准度 +0.5）✅

v3.7 和 v3.8 连续两轮都有人质疑 `_simple_functions` 的核心性。v3.9 换成了 `_engine_methods`，这个选择**确实更核心**：

- `_simple_functions`：只是复杂度判定的**输入之一**，是规则表的"数据源"
- `_engine_methods`：是表驱动分派的**核心机制**，路由决策完了靠它反射调用

**路由的完整链条是：** `_routing_rules`（决策表：选哪个引擎）→ `_engine_methods`（分派表：调哪个方法）。两者配合才是完整的"表驱动路由"。

缺了 `_engine_methods`，路由决策完了还得写 `if engine == "python": return _eval_python(...)` 这种硬编码分支——那就不是"表驱动路由"了，只是"表驱动决策 + 硬编码分派"。

**附录A的论证也很扎实，** 把6个候选属性列出来对比，逐一说明为什么不选，最后落脚到 `_engine_methods`。不是"我觉得这个好"，而是"对比下来这个最核心"。

## 三、不足的地方（4个问题，都不算严重）

### 问题1：架构层次图中 MetaEngine ↔ FormulaRouter 的双向箭头不准确 ⚠️

v3.9 架构层次图里，MetaEngine 和 FormulaRouter 之间用的是双向箭头 `◄────►`，暗示两者是互相调用的双向关系。

**但实际情况是单向的：** MetaEngine 调用 FormulaRouter，FormulaRouter 不会反过来调用 MetaEngine。FormulaRouter 是纯计算路由层，无副作用、无事件、无反向依赖——这一点文档自己在"发出事件"小节也说了："无。纯计算路由层，无副作用、无事件。"

**同样的问题也出现在 DynamicCell 和 DynamicFlow 之间。** 节点和边是结构组成关系，不是互相调用的双向关系。用双向箭头容易让人产生"它们互相调用"的误解。

**建议：** 架构层次图里，同一层的类之间不要用箭头（或者用虚线表示"同层协作"），把箭头留给跨层的方向关系。箭头是有方向语义的，不要乱用。

### 问题2：依赖关系图中 ConfigStore → FormulaRouter 的"配置注入"不准确 ⚠️

v3.9 依赖关系图里，ConfigStore 有两个"配置注入"箭头，分别指向 MetaEngine 和 FormulaRouter。

**但实际代码中 FormulaRouter 并不直接依赖 ConfigStore。** 看 FormulaRouter 的 `__init__`：

```python
def __init__(
    self,
    data_query: Optional[DataQuery] = None,
    hqchart_provider: Optional[Any] = None,
    python_engine: Optional[PythonFormulaEngine] = None,
    cache: Optional[FormulaCache] = None,
):
```

它接收的是 `data_query`、`hqchart_provider`、`python_engine`、`cache`，没有 `config_store`。它的配置（`_routing_rules`、`_engine_methods`、`_simple_functions`）是自己从 JSON 文件加载的，不是通过 ConfigStore 注入的。

MetaEngine 才是直接从 ConfigStore 拿配置的（`engine.py:735: self.tables = config_store._tables`）。

**这个问题属于"方向对但路径错"——** FormulaRouter 确实需要配置，但不是从 ConfigStore 来的。对于架构文档来说，这个误差可以接受，但如果追求极致精准，应该修正。

### 问题3：数据流图中"行情适配器 → ConfigStore"的箭头标注有误 ⚠️

数据流图里，行情适配器(tq) 指向 ConfigStore 的箭头标注是"股票池配置"。

**这不对。** 行情适配器是提供行情数据的，配置数据来自配置文件（或 ConfigStore 自己加载的 JSON）。行情适配器和 ConfigStore 之间没有直接的数据流向。

正确的关系应该是：
- 行情适配器 → MetaEngine：提供行情 tick 数据
- ConfigStore → MetaEngine：提供配置表数据

两者都是 MetaEngine 的输入，但它们之间没有直接关系。

**同样，** "行情适配器 → DataQuery"的关系也值得商榷。DataQuery 是独立的数据查询组件，不是行情适配器的下游。行情适配器提供的是实时 tick，DataQuery 提供的是历史 K线——两者是平行的数据源，不是上下游。

### 问题4：本质一句话连续两轮没改——不是问题，但可以再想想 ⚠️

v3.8 和 v3.9 的本质一句话都是一样的：
> "股票池是行情驱动的有向图过滤器，股票经边公式筛选后在节点间流转。"

文档说"再减字会损伤精度"，这个判断是对的。**但不减字不等于不能优化。** 比如：
- 能不能让它更有"架构感"？比如突出"表驱动"或"双引擎"这些核心设计？
- 能不能更精准地描述"有向图"的类型？比如"有向无环图"（如果确实是DAG的话）？

**不过这是吹毛求疵了。** 30字版本已经很好，不改也完全没问题。
