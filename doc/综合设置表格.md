# 股票池综合设置表格（DZH 真实设计 — 边批量+深度优先递归版）

> 基于 DZH 原版截图（超赢7号-1~7.png + CYS-股票1-1~4.png）与 `buildTableRows()` 算法的结构分析。
> 2026-06-19 修正：算法从「旧版BFS（先池声明→再出边）」修正为**边批量+深度优先递归**模式，与 DZH 和 MetaCore 实际实现一致。

## 〇、核心结论

### 0.1 表格的物理结构 = 3 列

```
┌──────────────────┬──────────────────────────────┬──────────────────────┐
│   流程标识        │   条件 / 属性                │   时序 / 操作        │
│   (左列 ~22%)    │   (中列 ~52%)                │   (右列 ~26%)        │
│                  │                              │                      │
│  池标签 (有/无   │  备选范围 / 状态属性 / 条件  │  重载模式 / 时序参数 │
│       └─▶)      │       + [设置]               │       + [设置]       │
└──────────────────┴──────────────────────────────┴──────────────────────┘
```

### 0.2 行的种类 = 3 种

| 行类型 | 数量 | 左列特征 | 中列内容 | 右列内容 |
|--------|------|----------|----------|----------|
| **备选池行** (`source`) | 1 行 (固定首行) | 备选池标签，**无 └─▶** | 备选范围 + 状态股票数 | 重载模式 |
| **状态池声明行** (`pool-decl`) | 状态池数 (每个池 1 行) | 状态池彩色标签，**无 └─▶** | 状态属性 (hold/轨迹/声音/收益) | 空 |
| **条件边行** (`edge`) | 复合边数 (每条边 1 行) | **带 └─▶ 拐角箭头** + 目标池彩色标签 | 条件描述 + [条件设置] | 时序参数 + [时序设置] |

**关键视觉特征**：
- **池声明行 vs 条件边行 的左列标签颜色可以相同**，但前者无箭头、后者有箭头
- **池和边严格分离**：不带箭头的行是池声明，带箭头的行是转移边
- **每个池只出现一次**（作为声明行），**每条边只出现一次**

### 0.3 "池" 和 "边" 严格分离

> **用户原话**："池是池，边是边，不带箭头的和带箭头的分开研究"

| 元素 | XML 类型 | 在表格中 |
|------|----------|----------|
| **池 (Pool)** | `type=200/8/202/7` | **只作为声明行**出现在表格中（每个状态池 1 行，备选池也是 1 行） |
| **条件 (Condition)** | `type=201` | **不独立成行**！作为"满足自设定计算公式转移"文字挂在条件边行的中列 |
| **复合边 (Edge)** | 上游边 (`attr=4096`) + 下游边 (`attr=4097`) 配对 | **每条复合边 = 1 个条件边行**，左列记为 `└─▶目标状态池` |

**边的命名规则**：
- 条件边行左列显示 `└─▶目标状态池`
- 该边代表 `源状态池 ─▶ 目标状态池` 的转移关系
- 具体的源状态池由递归层级和缩进隐含表达

## 一、算法说明：边批量 + 深度优先递归

### 1.1 `buildTableRows()` 算法伪代码

```javascript
function buildTableRows() {
  rows = []
  visited = {}

  // 对每个源池启动递归遍历
  sourcePools.forEach(sourcePool => {
    // 输出源池声明
    rows.push({type: 'source', cell: sourcePool, depth: 0})
    visited[sourcePool.id] = true

    // 递归处理子树
    processPoolRecursive(sourcePool, 0)
  })

  function processPoolRecursive(pool, depth) {
    // Phase 1: 批量输出该池的所有 EDGE 行（按 edgeIndex 排序）
    poolEdges = collectOutgoingEdges(pool).sort(byEdgeIndex)
    newPools = []

    poolEdges.forEach(edge => {
      rows.push({type: 'edge', cell: edge.targetPool, depth: depth + 1, ...})
      if (!visited[edge.targetPool.id]) {
        visited[edge.targetPool.id] = true
        newPools.push(edge.targetPool)
      }
    })

    // Phase 2: 对每个新池：输出声明并立即递归其子树（深度优先）
    newPools.forEach(targetPool => {
      rows.push({type: 'pool-decl', cell: targetPool, depth: depth + 1})
      processPoolRecursive(targetPool, depth + 1)
    })
  }
}
```

**算法要点**：
1. 从备选池出发，对每个源池启动**深度优先递归遍历**
2. **Phase 1（边批量）**：先批量输出当前池的所有出边行（按 `edgeIndex` 排序），同时收集首次遇到的目标池
3. **Phase 2（池声明+递归）**：对每个新发现的目标池，先输出其声明行，再**立即递归**进入其子树（深度优先）
4. `visited` 保证**每个池只声明一次**
5. `depth` 用于控制左列缩进

### 1.2 行数公式

```
总行数 = 1(备选池) + 状态池数 + 复合边数
```

### 1.3 输出顺序示例（超赢7号 片段）

```
depth=0  [source]     ▣ 沪深A股                          ← 备选池声明
depth=1  [edge]       └─▶ 初步筛选                       ← 沪深A股的出边(批量)
depth=1  [edge]       └─▶ 超赢备选                       ← 沪深A股的出边(批量)
depth=1  [edge]       └─▶ 强势整理                       ← 沪深A股的出边(批量)
depth=1  [edge]       └─▶ 英雄榜                         ← 沪深A股的出边(批量)
depth=1  [pool-decl]    初步筛选                          ← 第1个新池声明 + 立即递归
depth=2  [edge]       └─▶ 超赢价值A                       ← 初步筛选的出边
depth=2  [edge]       └─▶ 超赢价值B                       ← 初步筛选的出边
depth=2  [pool-decl]    超赢价值A                         ← 声明 + 递归
...
depth=1  [pool-decl]    超赢备选                          ← 第2个新池声明 + 递归
depth=2  [edge]       └─▶ 超赢强势                        ← 超赢备选的出边
depth=2  [edge]       └─▶ 超赢买点                        ← 超赢备选的出边
depth=2  [edge]       └─▶ 超赢追踪                        ← 超赢备选的出边
...（依此类推）
```

### 1.4 新旧算法对比

| 维度 | 旧版 BFS（已废弃） | 新版：边批量+深度优先递归（当前） |
|------|-------------------|-------------------------------|
| 遍历策略 | 队列式广度优先 | 递归式深度优先 |
| 单池处理顺序 | 先输出**池声明** → 再输出所有**出边** | 先批量输出所有**出边** → 再逐个输出**池声明**并递归 |
| 输出序列模式 | `[source] → [pool-decl] → [edge] → [edge] → [pool-decl] → [edge]` | `[source] → [edge] → [edge] → [pool-decl] → [edge] → [pool-decl]` |
| 与 DZH 一致性 | ❌ 不一致 | ✅ 与 DZH 原版及 MetaCore 实现一致 |

## 二、行的渲染规则

### 2.1 备选池行 (`type=source`, `depth=0`)

```
┌──────────────────┬──────────────────────┬──────────────────────┐
│ ▣ 沪深A股         │ 备选范围: SH#上证    │ 每次启动载入股票     │
│   (无 └─▶)        │ SZZ#中小企业         │ [设置]               │
│                  │ 状态中有股票: 0只    │                      │
│                  │ [备选范围设置]       │                      │
└──────────────────┴──────────────────────┴──────────────────────┘
```

- 左列：备选池标签，**无箭头**
- 中列：备选范围 + 股票数 + [备选范围设置]
- 右列：重载模式

### 2.2 状态池声明行 (`type=pool-decl`, `depth>=0`)

```
┌──────────────────┬──────────────────────┬──────────────────────┐
│   初步筛选        │ 进入后保持:18小时    │                      │
│   (无 └─▶)        │ 不记录轨迹           │                      │
│                  │ 进入时发出声音       │                      │
│                  │ [状态属性设置]       │                      │
└──────────────────┴──────────────────────┴──────────────────────┘
```

- 左列：状态池彩色标签，**无箭头**
- 中列：状态属性（hold/轨迹/声音/收益）+ [状态属性设置]
- 右列：**空**

### 2.3 条件边行 (`type=edge`, `depth>=1`)

```
┌──────────────────┬──────────────────────┬──────────────────────┐
│ └─▶ 初步筛选     │ 满足自设定计算公式转移│ 开盘后0秒执行        │
│                  │ [条件设置]           │ 执行19800秒          │
│                  │                      │ 执行间隔时间:60秒    │
│                  │                      │ 执行次数:-146        │
│                  │                      │ [时序设置]           │
└──────────────────┴──────────────────────┴──────────────────────┘
```

- 左列：`└─▶` + 目标池彩色标签（橙色箭头 `#f39c12`）
- 中列：条件描述（"满足自设定计算公式转移" 或 "无条件转移"）+ [条件设置]
- 右列：begin/begint/endt/interval/count + [时序设置]
